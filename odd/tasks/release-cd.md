# Release CD

## Objective

Publish signed Android APKs for both variants to GitHub Releases whenever a version tag is pushed.

## Problem

The repository is public at https://github.com/JohnyYen/moneyforge with CI, but nothing builds a native APK. The Kotlin capture module has never compiled, and the local machine cannot download the Gradle toolchain.

## Why

GitHub Releases is the only distribution channel for now. The Full variant (SMS capture) cannot ship on Google Play anyway, and a Play developer account is not available.

## Scope

- Release signing for `expo prebuild` output, read from environment variables.
- A tag-triggered workflow that builds the `play` and `full` variants on GitHub runners, signs them, and attaches them to a GitHub Release with SHA-256 checksums.
- A manual dry run (`workflow_dispatch`) that builds and uploads artifacts without publishing.
- README install and release instructions.

Out of scope: the Google Play upload job (deferred by the user), F-Droid or IzzyOnDroid submission.

## Constraints

- The keystore lives outside the repository at `~/.config/moneyforge/release.jks`. CI reads it from the secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, and `ANDROID_KEY_PASSWORD`. Certificate SHA-256: `9C:F3:34:A2:28:C7:5E:DF:AB:E7:DD:59:54:EC:4E:6A:C5:5F:1C:0C:6D:BA:83:40:B3:2C:4C:95:97:4F:93:B2`.
- `android/` is generated by prebuild and gitignored, so signing must come from a config plugin, not a hand-edited Gradle file.
- Without the signing variables, local and CI builds keep working with debug signing.
- The tag version must match `version` in `app.config.ts`.

It adds a `release` signing config guarded by `if (System.getenv('MONEYFORGE_KEYSTORE_PATH'))` and makes `buildTypes.release` use `System.getenv('MONEYFORGE_KEYSTORE_PATH') ? signingConfigs.release : signingConfigs.debug`. Decisions:
- Gradle reads the environment at configuration time, so no secret or keystore path is ever written into `android/`. Without the variables, release stays debug-signed, so local builds keep working.

If either is missing it throws at prebuild instead of silently shipping a debug-signed release. It also throws on a Kotlin build script.
- An `@generated moneyforge-release-signing` marker makes a second run a no-op.

## R2 done

Route: delegated writer, same unit as R1.

What changed: `.github/workflows/release.yml` with three jobs.
- `verify-version` reads `version` from `app.config.ts` and, on a tag, fails when the tag minus `v` differs.
- `build` runs a `[play, full]` matrix: prebuild, decode the keystore, `./gradlew assembleRelease`, check the certificate with `apksigner verify --print-certs`, rename to `moneyforge-<variant>-<version>.apk`, upload the artifact, and delete the keystore in an `if: always()` step.
- `release` runs only on a tag push, with `contents: write`. It writes `SHA256SUMS.txt` and runs `gh release create --verify-tag --notes-file ... --generate-notes` with both APKs and the checksums. The notes say play asks for no SMS permission and full adds opt-in SMS capture.

Decisions:
- The version comes from a regex over `app.config.ts`, not `expo config`. The check then needs no install and fails fast. A missing match fails the job.
- JDK 17 (temurin): `node_modules/react-native/gradle/libs.versions.toml` pins AGP 9.2.1, which needs JDK 17 or newer, and the React Native Gradle plugins use `jvmToolchain(17)`.
- No `android-actions/setup-android`: the ubuntu runner image ships the SDK with licenses accepted, and AGP downloads the platform (compileSdk 37), build tools 37.0.0, and NDK 27.1 it needs.
- `gradle/actions/setup-gradle@v4` caches Gradle and validates the wrapper.
- Without `ANDROID_KEYSTORE_BASE64` the build falls back to debug signing with a warning and skips the certificate check. A tag build without it fails before assembling. In this repository the secret is set, so dry runs sign too.
- The keystore path goes to `GITHUB_ENV` only after decoding. Passwords are passed straight from secrets to the Gradle step and never echoed.
- Concurrency group `release-<ref>`. Branch dry runs cancel older runs; tag runs never cancel.
- No Google Play job, as agreed.

Verification:
- YAML parse with `js-yaml`: three jobs, build steps in the intended order.
- The version regex run locally returned `0.1.0`. `v0.1.0` matched and `v0.2.0` was detected as a mismatch.
- The notes heredoc rendered locally with backticks intact. The digest pipeline turned a lowercase `apksigner` line into the expected uppercase fingerprint.
- `actionlint` is not installed, so it did not run.

Not run: no native build ran. The first compile happens in R3 on GitHub.

Commit: `ci: publish signed APKs to GitHub Releases on version tags`.

## R3 part 1

Route: delegated writer (two workflow files plus this document).

Why: `workflow_dispatch` cannot run a workflow that is not on the default branch, and the dry run must not touch `main`. The approved R1/R2 review also left non-blocking advisories.

What changed:
- `release.yml` triggers: one `push` key with `branches-ignore: [main]`, `tags: ['v*']`, and `paths` limited to `.github/workflows/release.yml`, `plugins/**`, `modules/**`, `app.config.ts`, `package.json`, `pnpm-lock.yaml`. `workflow_dispatch` stays.
- `verify-version` outputs `trusted`: true only for `refs/tags/v*` or `refs/heads/main`.
- `build`: decode keystore, signed assemble, and certificate check run only when trusted; those are the only steps that receive signing secrets. Untrusted refs run a separate assemble step with no secret env, so the plugin falls back to debug signing. A trusted ref without `ANDROID_KEYSTORE_BASE64` now fails instead of warning (this replaces the separate "Refuse to publish an unsigned build" step).
- Untrusted builds are named `moneyforge-<variant>-<version>-unsigned-check.apk` and uploaded as `unsigned-check-apk-<variant>`. The release job downloads `apk-*` only and runs only on a `refs/tags/v*` push, so check builds never reach a release.
- `release`: if the release already exists, `gh release upload --clobber` replaces its assets; otherwise `gh release create` as before.
- Every action in `release.yml` and `ci.yml` is pinned to a commit SHA with a version comment.

Decisions:
- GitHub does not evaluate `paths` for tag pushes, so one `push` key expresses both: every `v*` tag runs, and `paths` only filters branch pushes. `branches-ignore` and `tags` can coexist; only `branches` with `branches-ignore` cannot.
- Pushes to `main` do not trigger the workflow; main signs only through a manual run.
- R2 readability suggestions (version regex, digest pipeline, plugin config block, test count) were left as they are: without a concrete change they were not clearly better, and leaving the plugin untouched keeps its tests unchanged.
