# Release CD

## Objective

Publish signed Android APKs for both variants to GitHub Releases whenever a version tag is pushed.

## Problem

The repository is public at https://github.com/JohnyYen/moneyforge with CI, but nothing builds a native APK. The Kotlin capture module has never compiled, and the local machine cannot download the Gradle toolchain.

## Why

GitHub Releases is the only distribution channel for now. The Full variant (SMS capture) cannot ship on Google Play anyway, and a Play developer account is not available.

## Scope

- Release signing for `expo prebuild` output, read from environment variables.
- A tag-triggered workflow that builds the `play` and `full` variants on GitHub runners, signs them, and attaches them to a GitHub Release with SHA-256 checksums.
- A manual dry run (`workflow_dispatch`) that builds and uploads artifacts without publishing.
- README install and release instructions.

Out of scope: the Google Play upload job (deferred by the user), F-Droid or IzzyOnDroid submission.

## Constraints

- The keystore lives outside the repository at `~/.config/moneyforge/release.jks`. CI reads it from the secrets `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, and `ANDROID_KEY_PASSWORD`. Certificate SHA-256: `9C:F3:34:A2:28:C7:5E:DF:AB:E7:DD:59:54:EC:4E:6A:C5:5F:1C:0C:6D:BA:83:40:B3:2C:4C:95:97:4F:93:B2`.
- `android/` is generated by prebuild and gitignored, so signing must come from a config plugin, not a hand-edited Gradle file.
- Without the signing variables, local and CI builds keep working with debug signing.
- The tag version must match `version` in `app.config.ts`.

## R1 done

Route: delegated writer (two non-trivial files plus a workflow).

What changed:
- `plugins/with-release-signing.js`: a `withAppBuildGradle` plugin. It adds a `release` signing config guarded by `if (System.getenv('MONEYFORGE_KEYSTORE_PATH'))` and makes `buildTypes.release` use `System.getenv('MONEYFORGE_KEYSTORE_PATH') ? signingConfigs.release : signingConfigs.debug`. The path and passwords come from `MONEYFORGE_KEYSTORE_PATH`, `MONEYFORGE_KEYSTORE_PASSWORD`, `MONEYFORGE_KEY_ALIAS`, and `MONEYFORGE_KEY_PASSWORD`.
- `plugins/__fixtures__/app-build.gradle`: `android/app/build.gradle` copied verbatim from `node_modules/expo/template.tgz` (SDK 58).
- `plugins/with-release-signing.test.ts`, and the plugin registered in `app.config.ts` for both variants.

Decisions:
- Gradle reads the environment at configuration time, so no secret or keystore path is ever written into `android/`. Without the variables, release stays debug-signed, so local builds keep working.
- The plugin edits two verbatim template anchors: the `signingConfigs { debug { storeFile file('debug.keystore')` block, and the `// see https://reactnative.dev/docs/signed-apk-android.` comment followed by `signingConfig signingConfigs.debug` in `buildTypes.release`. If either is missing it throws at prebuild instead of silently shipping a debug-signed release. It also throws on a Kotlin build script.
- An `@generated moneyforge-release-signing` marker makes a second run a no-op.
